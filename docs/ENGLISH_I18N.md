# English i18n 实施说明（可交给 Cursor）

本文用于给 LiteConnect / LiteAI 增加完整的美式英语界面。先完成语言包，再接通语言切换，不需要第三方翻译 API。

## 1. 工作量与交付目标

统计基线：2026-10-24，提交 `c262d8d`。开始前应重新读取源码，不能把本文的数量当作永远不变的验收值。

| 范围 | 全部词条 | 含中文、需要翻译 |
| --- | ---: | ---: |
| 渲染进程，31 个模块 | 3,031 | 3,008 |
| Electron 主进程 | 96 | 96 |
| 合计 | 3,127 | 3,104 |

相同中文原文去重后有 2,707 段，约 25,377 个汉字。重复短句可复用初稿，但必须按上下文复核，例如“库”可能是 database、schema 或 library。

英文包必须包含全部 3,127 个 key，而不是只包含 3,104 个中文 key。其余 23 条主要是品牌名、技术名和占位符，可以沿用原值。

完成后应达到：

- 设置中可以选择“简体中文 / English”，切换后保存偏好，重启后仍生效。
- 普通窗口、独立 SSH / 数据库窗口以及主进程通知使用一致的界面语言。
- 中文行为保持兼容；英文 key 完整，不依赖中文 fallback 掩盖漏译。
- 英文模式下，内置 AI 默认回复语言跟随界面语言；用户明确要求和自定义提示词优先。
- 命令、协议字段、用户数据、服务器输出不因切换界面语言而改变。
- 本次不需要翻译 README 和整套开发文档，也不需要改服务器。

## 2. 最快的工作方式

直接用 Cursor 的模型翻译 TypeScript 语言文件即可。第三方翻译服务只能代替生成初稿，仍需保护插值、校对术语和接入应用；本项目没有必要为这次工作增加翻译 SDK、API Key 或运行时请求。

按下面顺序进行：

1. 先看本说明、现有语言文件和调用它们的界面，形成统一术语。
2. 在新目录中逐模块翻译，保持文件结构；每完成一个模块就检查 key 和插值。
3. 大文件按对象分段处理，持续写入实际文件，避免一次生成数千条导致漏译或截断。
4. 英文包完整后再启用语言切换，接通主进程、持久化和多窗口同步。
5. 扩展自动检查，补查用户可见的硬编码中文，最后统一验收。

不要逐词条向用户确认。语义不确定时，先查调用点和相邻文案；只有会影响产品行为的歧义才记录为待确认项。

## 4. 翻译规则

### 4.1 结构和代码

- 只翻译字符串值，保留 key、对象层级、模块导入和导出结构。
- 不修改中文包中的原文；为新增设置或抽取硬编码文案增加 key 时，中英文同时补齐。
- 使用 UTF-8，不加新依赖，不改变业务逻辑、权限或连接行为。
- 不删除看起来没被直接引用的 key。项目存在动态拼接 key，静态搜索不能证明它未使用。
- 不用 `...zhCN` 补齐英文词条，也不要用中文原文作为“已完成”的英文翻译。
- 中文语言文件含 `as const`，不要用 `satisfies typeof zhCN` 强迫英文值匹配中文字符串字面量。类型约束应只校验 key 结构，叶子值允许任意字符串。

### 4.2 插值与特殊语法

- 完整保留每个命名插值及其出现次数，如 `{count}`、`{host}`、`{port}`、`{error}`、`{name}`、`{path}`。
- 可根据英文语序调整插值位置，不能重命名、遗漏、增加没有传入的参数。
- 保留字符串中的换行、Markdown 代码标记及有意义的格式。
- `{'@'}` 是 vue-i18n 的字面量语法，不能改成裸 `@`。其他字面量转义、linked message 等语法也要保持有效。
- 英文缩写、撇号和引号需要按 TypeScript 字符串规则正确转义。
- 前端用 vue-i18n 编译器；主进程目前只用简单的 `{name}` 替换。不要给主进程文案直接引入前端专用语法。

示例：

```ts
// 中文
selectedCount: '已选 {count} 项',
connectFailed: '连接 {host}:{port} 失败：{error}',
urlExample: "mysql://user{'@'}host:3306/db",

// 英文
selectedCount: 'Selected: {count}',
connectFailed: 'Failed to connect to {host}:{port}: {error}',
urlExample: "mysql://user{'@'}host:3306/db",
```

处理单复数时先检查现有调用方式。短状态可以使用 `Selected: {count}` 等自然表达；不能只向译文加入复数分支而不确认调用端传入了正确的复数参数。

### 4.3 保留原样的内容

- 产品和协议名：LiteConnect、LiteAI、SSH、SFTP、Docker、MCP、SQL、MySQL、PostgreSQL、Oracle 等。
- 工具名和协议字段：`exec`、`read_file`、`connectionId`、`sessionId`、`risk`、`read`、`write`、`privileged`、状态枚举和错误码等。
- 命令语法、SQL 语法、选项、环境变量名、文件扩展名、URL 结构、路径和配置字段。
- 用户输入、连接名称、备注、分组名称、模型自定义名称及自定义提示词。
- 服务器的 stdout / stderr、日志、查询结果和远端文件内容。

示例中的说明文字或 SQL 注释可以翻译，但实际命令、连接串和 SQL 必须仍然可用。不要做全仓中文字符串替换。

### 4.4 文案风格

- 使用简洁、自然的美式英语，按钮用动词，标题尽量短，避免把中文逐字翻成冗长句子。
- 普通标签优先 sentence case，例如 `Command execution history`、`New connection`。
- “关闭”“断开”“取消”“停止”必须区分，不能一律翻成 Close。
- “工具调用成功”不等于“服务器操作目标已验证完成”，不要把状态译得比实际含义更强。
- 含风险和数据丢失含义的确认文案不能为了简短而省略后果。

术语建议：

| 中文概念 | 英文 |
| --- | --- |
| 连接 / 连接配置 | Connection / connection profile，按上下文 |
| 服务器 / 主机 | Server / host，按上下文 |
| 会话 | Session；AI 对话使用 conversation |
| 对话 / 历史对话 | Conversation / conversation history |
| 命令执行记录 | Command execution history |
| 断开连接 | Disconnect |
| 关闭会话 | Close session / Close conversation |
| 取消操作 / 停止执行 | Cancel / Stop |
| 执行中 / 已完成 / 失败 | Running / Completed / Failed |
| 等待审批 / 允许 / 拒绝 | Awaiting approval / Allow / Deny |
| 只读 / 修改 / 提权 | Read-only / Write / Privileged，按具体权限说明 |
| 工作区 / 分组 / 凭据 | Workspace / Group / Credentials |
| 定时巡检 | Scheduled checks |
| 命令片段 | Snippet |
| 数据库 / 模式 | Database / Schema |
| 查询 / 事务 / 提交 / 回滚 | Query / Transaction / Commit / Roll back |
| 本地 / 远端 | Local / Remote |

## 5. 接通语言切换

仅添加英文文件不代表功能完成。以下接入点都需要处理：

### 5.1 渲染进程

- 在 `src/i18n/index.ts` 注册 `en-US`，让 `SUPPORT_LOCALES` 和 `AppLocale` 同时支持中文和英文。
- 默认继续使用 `zh-CN`，保留中文 fallback 供异常降级；验收时仍要求英文 key 完整。
- 保持纯 TS 调用方使用现有 `t()` 入口，不在各组件分别维护语言状态。
- 更新 `document.documentElement.lang`。
- 检查在模块初始化时就调用 `t()` 的静态数组或对象。需要随语言变化的菜单、标签、校验消息应由 computed 或函数生成，避免切换后仍显示旧语言。
- 日期、时间、数字和排序里硬编码的 `zh-CN` / `zh` 要按用途检查；只调整界面格式，不改变协议、数据存储格式和 SQL 行为。

### 5.2 设置、持久化与主进程

当前入口为右上角齿轮 → 应用 → 顶部独立的“界面语言 / Language”选项，选择“简体中文 / English”后点击底部保存。设置搜索支持“语言”“language”“English”。

初始基线中的 `setAppLocale()` 仅写渲染进程 localStorage，`setMainLocale()` 尚未接入。本轮已补齐语言持久化和同步；后续维护需同时检查以下环节。

- 在 `src/components/settings/SettingsApp.vue` 提供语言选择；通过 `useSettingsDraft.ts` 接入现有保存 / 取消机制。
- 按现有设置架构，在主进程设置存储中保存经过白名单校验的 locale，作为持久化来源。
- 通过已有 preload / IPC 分层增加必要的读取、保存和变更通知，并更新 `src/types/liteConnectApi.ts` 等对应类型；渲染层不能直接导入 Electron 实现。
- 首次升级时兼容已有 `LiteConnect.locale` 偏好；后续避免 localStorage 和主进程设置各自维护冲突值。
- 主进程启动时恢复语言并调用 `setMainLocale()`，保证启动后、尚未打开主窗口时的通知也正确。
- 保存语言后更新主进程并向各窗口广播，独立窗口不能各用一种语言；不会因切换语言重建 SSH 连接或清空聊天。
- 若托盘菜单或其他原生菜单的标签在创建时固定，需要在语言变更后更新；不要漏掉独立窗口入口。
- 同时补齐新增语言设置的中英文标签、帮助和设置搜索条目。

### 5.3 AI 默认语言

- 检查 `electron/i18n/zh-CN.ts` 中的 `ai.defaultSystemPrompt` 及其实际读取和持久化路径。
- 英文内置提示词默认用英语回答；用户明确要求其他语言时优先遵循用户。
- 不覆盖用户已经编辑的 system prompt，不把用户自定义提示词当作待翻译文本。
- 如果旧内置默认提示词已存入设置，按实际存储语义处理：仅可迁移能确认仍是旧内置默认值的内容，不能泛化替换所有中文提示词。
- `shared/aiSidebarPrompt.ts`、`shared/aiWorkspacePrompt.ts` 和权限说明等还有中文指令；区分模型内部指令和用户可见说明。内部指令不必为了“零中文”全部重写，但不能继续强制英文界面的默认回答使用中文。
- 不修改工具 JSON schema 的参数名、权限枚举、路由或审批规则。

## 6. 扩展自动检查

现有 `scripts/check-i18n-keys.mjs` 只检查中文包的引用和前端消息编译。**直接运行它通过，并不能证明英文翻译完整。** 请扩展它或新增同等检查，并接入 `npm run i18n:check`：

1. 分别校验前端、主进程中英文语言包的叶子 key 集合完全一致，缺少和多出的 key 都报错。
2. 检查对应字符串的命名插值及出现次数一致；前端应按消息语法解析，不能用把所有花括号都当插值的粗糙正则。
3. 对中英文前端字符串分别运行 vue-i18n 消息编译检查，报告具体文件、key 和原因。
4. 扫描英文包中的中文残留。确需保留的专有名称或示例应使用明确白名单，并记录理由，不能直接排除整个模块。
5. 保留现有中文引用完整性检查。动态 key 不能靠当前简单正则完全覆盖，因此还需要完整 key 集合对比。
6. 检查脚本应能捕获故意制造的缺 key、改错 `{count}`、非法裸 `@` 和漏译，然后恢复测试夹具；不要损坏实际语言包。

补查硬编码中文时，可从以下命令定位候选；结果包含注释、测试、内部提示词和协议样本，不能直接批量翻译：

```powershell
rg -n --glob '*.vue' --glob '*.ts' --glob '!*.test.ts' --glob '!**/i18n/**' '[\p{Han}]' src electron shared
```

优先抽取按钮、弹窗、通知、表单校验和最终展示给用户的错误消息。不要为了国际化修改内部错误码或依赖错误文本的程序判断；必要时保留内部结构化标识，只翻译显示层。

## 8. 可直接粘贴给 Cursor 的任务

```text
请先阅读 docs/ENGLISH_I18N.md，再为本仓库实现完整的 en-US 国际化。
```
