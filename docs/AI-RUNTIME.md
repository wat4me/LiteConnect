# AI 执行服务

`electron/ai/execution/executionService.ts` 提供统一的 `AiExecutionService`，供侧栏、LiteAI 工作区和定时巡检调用。它不接收 `WebContents`、窗口或 Vue 组件，页面事件由 IPC 适配层转换成可选监听器。

## 运行入口

`run(request, observer?)` 接收四类明确身份：

- `requestId`：一次模型请求，供取消和工具确认使用。
- `historyId` 与 `target.threadId`：历史存储与具体对话，不从当前页面推断。
- `target.sessionId`：已建立的 SSH 会话，仅用于目标工具执行。
- `owner`：调用方身份；交互客户端使用数字编号，无页面执行使用字符串编号。自动化建议每次运行采用独立身份，例如 `automation:<runId>`。

存储是模型上下文的唯一来源。调用方先保存用户请求、创建目标对话，再调用执行服务。不存在的对话或已断开的 SSH 会话会在模型调用前失败，不恢复其他对话或重建已删除的历史。

交互调用沿用动态权限设置；`automation` 调用强制只读，不继承全局自动执行权限，也不等待页面确认。无人值守的修改操作尚未开放。

## 中断、执行记录与结果验证

上下文压力统一由 `shared/aiContextPressure.ts` 计算，包含系统提示、会话资料、工具定义与当前模型可见消息，与累计计费用量分开。圆环在空闲时估算下次请求（含草稿和附件），生成时接收主进程压力事件；两端采用同一套预算和估算函数，数值为估算而非提供商精确分词结果。

模型可配置 `maxOutputTokens` 和 `compactionRetainTokens`。默认输出预留为 4k、小窗口最多占 20%；自动压缩在可用输入预算的 80% 附近触发，近期原文默认保留输入预算的 20%、最多 15k。每次工具续答前先裁剪长工具结果，再按需摘要已经完成的调用与结果，始终保留成对协议和完整执行记录。轮内摘要只影响本次模型请求；原始工具消息独立保存，后续完整轮次可进入持久化检查点。

点击输入框的上下文圆环或发送 `/compact` 可手动压缩。手动维护共享执行服务的历史锁、归属校验和取消通道，不创建聊天记录、不执行工具，也不消耗草稿。服务端确认上下文超限后，每轮回复最多恢复一次；恢复仅重发模型请求，不重跑已经执行的命令。适合单次调用的摘要尽量复用系统提示和工具定义，大历史仍分块摘要；提交检查点前验证内容缩小，原始聊天历史保持可查看。

工具执行前的检查点必须保存成功，保存失败会结束当前回复并阻止该调用执行；定时保存文本仍为尽力保存。取消后不启动同轮剩余工具，已运行工具按已返回、未执行或结果未知保留记录。远端连接或模型请求中断不代表修改已回滚，后续对话须先读取实际状态再决定剩余操作。

错误或中止的回复不重放未完成正文、推理或残缺工具协议，但会从 `toolRuns` 生成有长度上限的执行事实，带上目标服务器、参数、结果和后台任务编号。最多保留 16 项，优先保留可能产生修改的调用，明确标记省略和截断。上下文压缩也保留这些事实及未验证状态，避免压缩后遗忘已执行的修改。

工具调用出现未预期异常时，返回本次调用结果未知的记录，让同轮其他服务器调用继续；用户取消或检查点保存失败仍结束当前请求。模型已经返回工具调用片段后，后续流错误或工具不兼容错误不再降级为丢失工具上下文的纯文本请求。

OpenAI 兼容流必须有 `[DONE]` 或明确的 `finish_reason`；Claude 流必须完整结束消息及内容块。因输出限制、服务商拦截或流提前结束而未完整确认的工具调用不会执行，已输出文字保留并将回复标为失败。非流式回复同样拒绝明确的输出截断。

单机和多机提示统一要求修改后在原服务器执行必要的只读复查，分别说明已验证、失败和未验证项。工具返回、退出码为 0 或后台任务启动均不作为用户目标完成的证明。这是模型行为指引，执行层不凭字符串推断业务健康，也不保证模型一定正确选择验证方法。回归测试使用模拟 SSH 与模型覆盖上述执行边界。

## 依赖与监听

设置端口提供初始化、运行配置和历史限制。历史端口负责读取、保存、图片加载及压缩检查点。工具端口复用现有 SSH MCP runtime。

`onStream`、`onRecord` 是可选的过程和持久化记录监听器。缺少监听器或监听器报错，不影响模型执行和结果保存。交互调用可提供 `onApproval`，实际确认仍通过执行服务按调用方身份校验。

## 交互提问

`ask_user` 是应用内的交互工具，不调用 SSH，不要求服务器标识或风险申报。`shared/aiQuestions.ts` 定义模型参数与答案验证：一次 1–3 个问题，每题可提供 2–5 个选项、单选或多选，也始终允许文字回答。选项不预选，用户跳过返回 `cancelled: true`，不产生默认答案或执行许可。

工具先登记与请求、调用编号及窗口身份绑定的等待器，再发布 `question` 状态卡片并保存检查点。只有当前交互请求所属窗口能提交合法答案；重复、过期、越权、未知选项及未完整回答的提交不消费等待器。回答作为标准工具结果送给下一次模型调用，停止、销毁或重启不会伪造用户回答。若模型把提问和其它工具放在同一批，只处理第一个提问，其余工具明确标记未执行，等模型理解答案后再计划操作。

定时巡检和其他无人值守执行从模型工具列表移除 `ask_user`，同时移除提问指引，不进入等待用户的流程；异常的未提供工具调用也会立即返回不可用。操作审批独立生效，提问答案不更改权限模式。问题、答案和跳过记录随会话保存，并用于中断恢复与上下文压缩。

## 后台任务与生命周期

后台命令绑定调用方、对话和 SSH 会话，完成后仍由同一服务续接。短时间内完成的任务合并投递。AI 正忙时，在完整工具调用批次之后、下一次模型请求之前注入完成结果；如果结果在本次模型回复期间到达，即使模型已给出等待说明，也会在同一回复内继续处理。AI 空闲时才新建自动续接回复。结果通过完成事件入队，模型不需要轮询任务。

同一回复最多增加三次因完成结果而产生的额外续接步骤，工具轮次上限继续独立生效；超过限制的结果保留在队列中，交给空闲续接。连续空闲自动唤起仍最多三轮，新的主动调用重置唤起预算。

完成通知包含任务编号、终态、退出码和有长度上限的输出；收到后直接分析，不再次 `get_job` 确认完成。仅在用户要求查看进度，或推送输出被截断且确需补读时读取任务。聊天工具及其 `background` 参数统一提供此约定，外部 MCP 客户端仍使用主动读取接口。

忙时结果按实际顺序追加到 `apiMessages`，先完成持久化，再从队列确认消费；不插入工具调用与对应结果之间。空闲续接的初始结果仍通过 `backgroundNotice` 与 `contextHistory.continuation` 参与上下文准备。历史重放去重，中断和错误只保留已交付结果及执行事实，不重放未完成的助手结论；两条路径的结果都参与上下文压缩，并使用同一种结果卡片展示。任务在工具确认前完成时，绑定阶段检查任务快照并补入完成队列。

`selectConversation` 只修改对应调用方的会话选择；另一个调用方不会暂停本调用方的任务。`suppressBackground` 在新建对话前禁用旧对话通知，并等待该对话正在执行的自动续接终止。`abort` 和 `resolveApproval` 校验请求所属调用方。`abort` 停止模型回复并禁用续接；中断 SSH 后台命令仍须调用 `cancel_job`，侧栏的新建对话流程已执行这两步。

监听器关闭与调用方销毁分开处理：没有页面的任务可继续执行；通过 `onDisposed` 或 `disposeOwner` 明确销毁调用方时，取消其模型请求并清理结果队列。应用退出调用 `dispose`，释放任务完成订阅并中止活动模型请求。

## 预约任务

模型可以在 `exec` 上加 `startAfterMs`（1 分钟到 24 小时，须 `background=true` 且只针对单个会话）把一条命令推迟执行，并用 `note` 给操作者一句说明。创建时走与立即执行完全相同的权限门控：只读直接放行，修改或提权命令按当前权限模式弹出审批卡，审批卡展示的参数包含延迟时间；到点执行不再二次询问，只有策略永久拒绝的命令会在到点时失败。预约记录持久化在 `ai-deferred-jobs` 单例里，重启后恢复，同时在任务存储中以 `scheduled` 状态出现，`list_jobs`、`get_job`、`cancel_job` 和任务卡片都按普通任务处理。外部 MCP 客户端和无人值守巡检的 `exec` 收到 `startAfterMs` 会返回 `INVALID_ARGUMENTS`，不会静默立即执行；历史里的工具结果保留 `dueAt` 和 `note`，供重启后的上下文重放。

`electron/ai/schedules/deferredJobs.ts` 每 30 秒检查到期记录。到期时该主机有打开的会话，就在其中一个会话里以普通后台任务启动，任务 id 不变，并把结果绑定到拥有该会话的窗口，完成后沿用后台任务的投递路径回到原对话。没有会话时标记为等待连接，用户下次连上这台主机时立即执行，不会自动建立连接。到点时没有窗口拥有该会话，结果以 `backgroundNotice` 记录写入原对话，用户打开对话时可见，模型在下一次请求中按同一前缀识别。应用关闭时正在执行的预约命令标记失败并说明原因，待执行的记录保留并在启动后重新登记。工作区多机会话和无人值守巡检不提供预约。

时间输入有两种：相对延迟 `startAfterMs`，或本地时间 `startAt`（`YYYY-MM-DD HH:mm`，也接受带时区偏移的 ISO 8601），主进程按应用所在时区换算成延迟。每次请求的系统附加文本带一行本地日期和时区（不含时分，避免每分钟打破提示缓存），模型据此把"明早八点"换成 `startAt`；预约结果回传 `scheduledAtLocal` 与 `dueAtLocal`，模型应把到期本地时间告诉用户，换算错了可以取消重排。到期后超过 `MCP_SCHEDULE_GRACE_MS`（2 小时）仍没有可用会话的记录标记为过期，以失败结果写回对话而不再补跑；取消和过期的投递与运行结果一致：有窗口拥有该会话就走后台任务路径，否则直接写入对话。任务面板的预约行显示倒计时，展开后显示创建时间和预计执行的绝对时刻。

## 历史存储

AI 会话历史按主机存储，布局为"索引加一条消息一行"：`ai-session:<主机>` 单例只保存对话元数据和每个对话按时间排序的 `{ id, createdAt, role }`，消息体存在 documents 表的 `ai-msg-v2:<主机>:<对话>` 集合里，每条消息一行。流式回复的检查点和 `appendSessionHistory` 只写一行加索引，`contextCheckpoint` 只改索引；整库读取按对话逐个集合取回并走统一正规化。首次读到旧的整块 JSON 或 JSONL 时在一个事务里拆行迁移，原始数据保留在 `ai-session-v1-backup:<主机>` 以便恢复；定时任务的临时历史通过 `deleteAiHistory` 一并清理索引、备份和消息行。

消息行采用压缩形态：`segments` 的文本、`apiMessages` 中助手消息的正文与推理都改为引用记录自身 `content` / `reasoningContent` 的长度片段，与 `toolRuns` 完全一致的工具结果改为 `contentRef: 'toolRun'` 引用，工具结果在两处统一按 `AI_TOOL_RUN_CONTENT_MAX` 封顶；`normalizeAiHistoryRecord` 读取时展开，服务层与渲染端永远看不到压缩形态。渲染端保存当前对话和切换对话走 `ai:saveConversation`，只传当前对话的消息，由主进程替换该对话的行并返回线程摘要与选中的对话；删除、清空仍整库回写，但未变化的行会被跳过。

## 当前边界

LiteAI 工作区通过 `ai:openWorkspaceConnection` 选择已保存的连接并自动建立专用 SSH 会话，沿用凭据、主机密钥确认和交互认证流程。`electron/ai/workspace/workspaceConnections.ts` 按窗口和连接编号管理传输，合并并发连接、复用本工作区连接，关闭时校验归属；取消后迟到的连接也会释放。工作区传输不创建终端标签，不借用或关闭普通 SSH 窗口的连接。

工作区切换主机保留各主机当前对话和草稿，切换应用模块保留连接与任务。显式断开会取消该 SSH 会话的任务；窗口销毁会释放所属传输。主机验证完成通过专用事件路由回工作区，避免建立普通终端。两种界面共用执行服务与历史格式。

`electron/ai/schedules/scheduler.ts` 持久化管理本地巡检计划与执行记录，支持间隔、每天和每周固定本机时间，全局串行、限制运行时长，并在退出/重启时处理遗留记录。`shared/aiSchedules.ts` 统一验证时间配置与计算严格晚于当前时刻的下一次运行；缺少 timing 的旧计划保持按间隔运行。固定时间按本机日历计算，兼容夏令时与系统时区变化。调度只检查本地计划，不轮询 SSH 任务。计划的启动时刻和下次运行先持久化，随后才建立连接，避免重启重复启动与集中补跑。

`electron/ipc/aiScheduleExecutor.ts` 作为适配层复用凭据建立独立 SSH 连接，以计划专属 `automation` 身份调用执行服务，每次运行使用唯一请求编号和临时独立历史并在结束后清理。`foregroundOnly` 强制 exec 使用前台通道。完成报告和工具结果保留在计划执行记录中；取消与超时停止模型和连接。无人值守运行不会打开主机信任或 MFA 对话框，也不会接管已有交互验证。

`electron/ai/schedules/orchestrator.ts` 通过适配端口按计划串行或最多 5 台并行巡检最多 10 台主机，发布各主机进度，隔离上下文、连接和结果，一台失败不阻止其余主机。计划可指定服务商与模型；未指定时使用当前活跃配置。多主机结果通过无工具的模型请求汇总；主机报告作为不可信数据输入，整体健康等级不能被汇总降级。中断保留已完成主机结果，取消当前和后续目标。

`electron/ai/schedules/notifications.ts` 管理通用 JSON Webhook，地址和令牌通过设置密钥边界加密。执行服务和模型均不读取通知配置。调度器先保存巡检结果，再独立限时发送通知，同时释放执行槽并立即检查已到期计划。通知按执行编号更新当前快照，兼容发送期间编辑或删除计划；退出时中止所有发送，异步回调不再写存储。发送结果独立于巡检状态，不重试或在重启后重发。

LiteAI 交互会话支持用户手动选择 1 至 20 台已保存服务器。`electron/ai/workspace/workspaceScopes.ts` 持久化不可变管理范围，按窗口校验会话归属，通过主进程解析已连接的专用 SSH 会话；历史使用范围编号独立保存，与 SSH 侧栏的单主机历史分开。恢复原范围时必须连接全部选定服务器，任一目标断开时暂停发送，重新连接后继续原对话。

`shared/aiWorkspacePrompt.ts` 为模型提供不含凭据的服务器清单，并要求每次工具调用显式指定 `connectionId`；`electron/ai/tools/workspaceToolRouting.ts` 校验范围及后台任务、PTY 的目标归属，拒绝范围外连接和模型注入的运行时会话编号。审批和工具结果保留目标服务器标签。背景任务完成通知绑定原会话，不会切换到其他对话或主机；关闭范围会话会停止其自动续答，但保留历史和可复用连接。

交互会话共享多台主机的对话上下文，工具调用仍按模型调用顺序逐项执行；定时巡检则为每台主机使用独立上下文，可选择串行或最多五台并行并在最后汇总。SSH 侧栏 AI 继续固定操作当前终端。共享连接租约、自定义 cron 表达式和应用关闭后的系统级调度尚未接入；执行服务不自行扩展会话范围。

验证覆盖无页面执行、无页面后台续接、只读权限、监听失败、调用方隔离、历史并发、停止、目标失效和资源释放；均使用模拟 SSH/模型，不访问真实服务器。
