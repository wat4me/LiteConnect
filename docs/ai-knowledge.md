# 服务器知识文档

AI 输入区常驻的文档图标打开“服务器知识”。SSH 侧栏只显示当前连接；LiteAI 多服务器会话可在弹窗顶部切换会话范围内的服务器。新建对话后仍可使用同一连接的知识文档。独立的“会话资料”按钮、附件预览／刷新／来源探测及其增删 IPC 已移除，知识库是唯一的文档管理与模型附加入口。

## 旧会话资料迁移

启动 AI 服务时，应用按已保存服务器地址和端口关联旧会话资料；旧多服务器会话中的共享资料关联其原范围内的服务器。旧版按主机共享的资料也会迁入该主机原本共享历史的连接；迁入后按知识库的连接、地址、端口、账号身份独立管理。运行期间新添加的连接会在访问历史前补迁移。

默认资料和历史线程中不同的正文快照都会保留，完全相同的正文去重；同名不同内容使用不同文档，不覆盖已有知识。迁入文档默认按需读取，保留现有知识开关状态，新知识库默认关闭。迁移与索引、完成标记写入同一数据库事务，失败可重试；迁移完成后删除或编辑文档不会再次从旧记录导入。迁移可保留超出普通新建数量上限的已有资料，后续新建仍受上限约束，不为满足上限丢弃旧内容。

旧历史字段仅作为恢复数据保留，不再继承到新对话，不再直接加入系统提示词、请求预算或补全回退。知识开关关闭时，它们不会绕过开关继续全文发送；已经存在于历史消息中的内容不能撤回。

文档图标旁常驻“知识”开关，单服务器会话可直接启用／停用，按该服务器身份持久保存；停用仍可打开文档查看。首次没有文档时启用需确认存储与发送说明，再次启用已有文档时可直接切换。多服务器会话显示启用数量，点击进入管理并逐台设置，不批量改变其他服务器。AI 执行期间禁用切换，避免把正在发送的上下文误认为已撤回；停止后恢复操作。

## 存储与启用

首次点击“启用知识库”会说明存储位置和 AI 使用方式，确认后才创建知识记录。文档与历史版本保存在本机应用数据目录的 `liteconnect.sqlite`，弹窗显示完整路径。不会在本地家目录或服务器上创建 `.liteSSH`，也不需要修改远程文件权限。

启用表示允许将摘要、目录及 AI 按需读取的内容发送给当前配置的 AI 服务。请勿保存密码、私钥、令牌等秘密。可以随时“停止自动使用”：后续请求不再附加知识，AI 工具也拒绝读写；文档仍可手动阅读、编辑、导出、恢复和删除。已经发送给 AI 的内容及既有会话历史不会被撤回。

知识按已保存的连接 ID、主机、端口和 SSH 用户区分。修改地址、端口或账号后不会自动沿用旧知识；改回原身份可重新访问。更换同地址服务器时应手动检查旧记录，不将文档当作服务器事实的实时证明。复制连接会得到独立知识库。

## 文档管理

- 所有内容在同一个知识库中管理，编辑时可勾选“每轮附加”。短事实、固定路径和用户规则可以直接保存并勾选，无需另建来源文档或重复维护摘要；详细清单、步骤和排障记录默认按需读取。
- 优先记录可复用的“服务 → 路径／命令”：服务安装目录、配置和日志位置、已确认的更新／部署脚本路径及使用方式、验证过的启停命令或 systemd 单元。路径和用法需要证据，不根据名称猜测；尽量简短记录，避免自动扩写为整台主机的巡检报告。
- 空知识库启用时创建 `MEMORY.md`，默认每轮附加，也可以取消勾选。它继续支持原有条目格式：建议约 300 字符，此格式当前最多 6 条、共 600 字符，每条为单行、最多 160 字符。这只是初始编辑格式和预算，不是所有知识记录的统一条目限制；也可直接新建 Markdown 短记忆并勾选每轮附加。
- 来源关联可选，最多 3 份同服务器文档；只在需要追溯详细资料时关联。预览中可直接点击打开，改名不影响关联，删除后显示失效，不会自动匹配同名文档。移除失效关联后，独立记忆仍可保存。修改历史和版本恢复会保留关联及附加选项。
- 旧版自由文本记忆保留原文，编辑时可整理为条目，来源仍然可选。不会按标题猜测关联，也不会自动重写现有知识。临时负载、占用比例和扫描输出留在对话中，不反复作为长期事实附加。
- AI 保存规则明确排除瞬时状态：观测到的 PID、运行时长、实时 CPU／内存／swap 占用、负载、磁盘已用／剩余空间或使用率、当前进程／服务／容器状态及运行数量、临时会话和连接数。此规则同时适用于记忆和按需文档；普通巡检不应顺带建档。混合输出只提取有后续价值的稳定事实，没有新增长期信息就不保存。持久配置中的资源限制、容量、告警阈值与实时占用分开处理；主机用途、固定路径、用户规则和验证过的可复用操作步骤仍可记录。更新旧记录时也不应照抄其中的瞬时状态。这是系统提示词和工具描述对模型的约束，不是正文关键词过滤器；已有文档和用户手动编辑／导入不自动清理。
- 支持 Markdown 预览、编辑、新建、从本机导入和导出到用户选择的位置。导出的是已保存版本，编辑后应先保存。有来源的记忆导出附文档 ID，没有来源的记忆只导出正文；单独导入 Markdown 不会重建本机关联，如需关联可手动选择来源。导出不保留“每轮附加”选项，导入后默认按需读取。
- 每台服务器最多 20 份文档，每份正文最多 32 KiB（按 UTF-8 字节计算）。界面在超限时提示并阻止保存。
- 每份文档保留最近 5 个旧版本，标明时间和用户／AI 作者。恢复旧版本会创建新版本；删除会同时移除该文档的历史。
- 多个会话同时修改时按版本检查，过期编辑不会覆盖新内容；保留当前草稿，用户可刷新并重新整理。

## AI 工具

只有已启用服务器的会话才提供以下本地工具；它们不调用远程命令，也不向外部 MCP 服务暴露操作电脑文件的能力。

| 工具 | 行为 |
| --- | --- |
| `knowledge_search` | 在一个授权服务器内搜索标题和正文；空查询列出文档。 |
| `knowledge_read` | 按文档 ID 分段读取最新内容和版本。长文档使用 `nextOffset` 继续读取，并通过 `expectedRevision` 避免混合不同版本。 |
| `knowledge_save` | 普通记录传 `content`，短记忆可设置 `alwaysInclude: true`；`memory` 继续传 `memoryEntries: [{ text, documentIds? }]`。来源可省略或为空；提供时必须存在、属于同一服务器且不是摘要自身。现有文档必须带准确版本；更新未传附加选项时保留原值。没有任意本地路径参数。 |

每轮对话开始，应用附加已勾选记录的内容，以及预算内的文档目录和可选来源元数据。已经足够清楚的独立记忆可直接使用，不必再次读取来源；需要完整步骤、证据、未包含的信息或实时状态时再搜索／读取／核验。来源失效不能提供细节依据，但不会自动使独立用户记忆失效。来源有效性由应用校验，检索时机由模型判断，并非自动语义检索或强制拦截回答。

常驻内容和目录有总长度限制，多服务器、多记录时分配预算；截断时标记并提示 AI 按需读取全文或搜索完整目录。编辑界面说明“每轮附加”受上下文预算限制。旧自由文本记忆每台最多附加前 600 字符，原始全文仍保留。文档不能改变工具权限，也不能替代对实时服务状态的核验。

AI 更新遵循现有执行模式：“只读”禁止保存，“询问”需要确认，“自动执行”允许保存。即使模型把保存误报为只读，应用也按写入处理。保存结果提供“查看文档”，直接定位对应服务器及文档。

## 开发验证

`npm run test:ui -- --knowledge` 使用临时应用目录、真实 SQLite 存储与实际 Vue 组件，验证首次启用确认／取消、编辑、导入导出、冲突保留草稿、版本恢复、多服务器隔离和结果定位，以及中英文、三种主题和窄宽窗口。文件选择／保存对话框由测试替身提供，不访问真实用户知识；原生导出 IPC 的权限、取消和应用关闭行为另有单元测试。

工具执行测试通过模拟 AI 流验证读取、审批、保存和下轮工具加载，不调用真实模型或 SSH 服务器。
