# 服务器知识文档

AI 输入区常驻的文档图标打开“服务器知识”。SSH 侧栏只显示当前连接；LiteAI 多服务器会话可在弹窗顶部切换会话范围内的服务器。新建对话后仍可使用同一连接的知识文档。独立的“会话资料”按钮、附件预览／刷新／来源探测及其增删 IPC 已移除，知识库是唯一的文档管理与模型附加入口。

## 旧会话资料迁移

启动 AI 服务时，应用按已保存服务器地址和端口关联旧会话资料；旧多服务器会话中的共享资料关联其原范围内的服务器。旧版按主机共享的资料也会迁入该主机原本共享历史的连接；迁入后按知识库的连接、地址、端口、账号身份独立管理。运行期间新添加的连接会在访问历史前补迁移。

默认资料和历史线程中不同的正文快照都会保留，完全相同的正文去重；同名不同内容使用不同文档，不覆盖已有知识。迁入文档默认按需读取，保留现有知识开关状态，新知识库默认关闭。迁移与索引、完成标记写入同一数据库事务，失败可重试；迁移完成后删除或编辑文档不会再次从旧记录导入。迁移可保留超出普通新建数量上限的已有资料，后续新建仍受上限约束，不为满足上限丢弃旧内容。

旧历史字段仅作为恢复数据保留，不再继承到新对话，不再直接加入系统提示词、请求预算或补全回退。知识开关关闭时，它们不会绕过开关继续全文发送；已经存在于历史消息中的内容不能撤回。

文档图标旁常驻“知识”模式选择，单服务器可直接选择，按该服务器身份持久保存。多服务器会话显示启用数量，点击进入管理并逐台设置，不批量改变其他服务器。AI 执行期间禁用切换，避免把正在发送的上下文误认为已撤回；停止后恢复操作。

| 模式 | 自动附加与按需读取 | AI 新增／修改 | 用户手动管理 |
| --- | --- | --- | --- |
| 关闭 | 不再附加，AI 不能搜索或读取 | 禁止 | 已有文档仍可查看、编辑、导出、恢复和删除 |
| 只读 | 按“每轮附加”设置提供内容，允许搜索／读取 | 禁止 | 可新建、导入、编辑、导出、恢复和删除 |
| 可更新 | 与只读模式相同 | 按现有执行权限决定 | 可手动管理 |

首次没有文档时选择只读或可更新需确认存储与发送说明，再次启用已有文档时可直接切换。升级时，旧版关闭状态保持关闭，旧版已启用的知识库保留为可更新；不会自动改变已有文档。只读模式只限制 AI 写知识，不改变 SSH 命令、文件传输等操作的执行权限。

## 存储与启用

首次点击“启用知识库”会说明存储位置和 AI 使用方式，确认后才创建知识记录。文档与历史版本保存在本机应用数据目录的 `liteconnect.sqlite`，弹窗显示完整路径。不会在本地家目录或服务器上创建 `.liteSSH`，也不需要修改远程文件权限。

启用表示允许将摘要、目录及 AI 按需读取的内容发送给当前配置的 AI 服务。请勿保存密码、私钥、令牌等秘密。可以随时切换为“关闭”：后续请求不再附加知识，AI 工具也拒绝读写；文档仍可手动阅读、编辑、导出、恢复和删除。已经发送给 AI 的内容及既有会话历史不会被撤回。

知识按已保存的连接 ID、主机、端口和 SSH 用户区分。修改地址、端口或账号后不会自动沿用旧知识；改回原身份可重新访问。更换同地址服务器时应手动检查旧记录，不将文档当作服务器事实的实时证明。复制连接会得到独立知识库。

## 存储粒度与规模

知识保存在 SQLite 中，正文和结构化字段仍使用 JSON 编码；性能取决于每次读写的记录范围。旧格式将一个服务器的全部文档及历史装在同一条 JSON 中，读取一份正文也会解析其他文档的历史。

现在按知识范围维护轻量目录，将每份当前文档、每个历史版本分成独立记录，通过 SQLite 主键索引定位。AI 读取只加载当前文档，用户查看历史时才加载该文档的旧版本；搜索只读取目标知识范围内的当前正文，空搜索直接返回目录。保存只写入变更文档、一个归档版本和目录，清理超过五份的旧版本。目录仍保留受限的常驻内容预览，用于构建每轮提示词。

旧格式在首次读取正文或修改对应知识库时通过事务迁移，保留正文、版本、作者、来源、结构化系统关系和附加设置；未访问的知识库不会在启动时批量转换。失败时回滚原记录，可重试。数据库版本升级为 2，旧版应用会拒绝打开，避免将新格式覆盖成旧格式。备份与恢复应使用完整应用数据库。

组关系按成员身份建立内存反向索引，只计算当前会话相关的组；索引检测本进程修改、事务回滚和其他 SQLite 连接提交后失效。连接身份使用独立的轻量目录，增删、导入和地址／账号修改后同步失效，不在每次知识工具调用中复制、排序全部连接。启动时旧资料与工作区的关联只索引一次，迁移写入合并到事务中，已完成来源在后续启动时跳过。

建组成员选择支持按名称、地址和用户名搜索，长列表仅渲染可见行，搜索前后的选择保留；每组仍最多 100 台。保存数千台服务器不会将它们的全部知识发送给 AI；提示词只处理当前会话授权的服务器及相关组，共享组内容每轮附加一次，继续受总预算限制。

## 知识组与公共知识

同一套服务的服务器可以建立独立的“知识组”，集中维护共同目录、日志位置、发布流程和操作约定。知识组与连接列表的管理分组独立，每个服务器身份最多加入一个知识组；成员按已保存连接 ID、地址、端口和 SSH 用户绑定。修改地址、端口或账号后不会自动继承原组知识，用户可以在管理知识组时明确重新选择成员。

- 在连接列表点击“选择服务器并建知识组”后多选成员，或在 LiteAI 的服务器列表多选后点击“创建知识组”。多服务器会话的知识面板也提供“为这几台服务器共享知识”引导，可关闭且不反复显示。
- 建组时确认名称和成员，可填写公共知识，也可以留空后再添加。创建后直接打开组知识编辑区，无需连接服务器即可维护、导入导出和恢复公共文档；空组直接进入新文档草稿。创建界面说明本机存储、默认启用只读、向当前 AI 服务发送和使用范围；不会合并或修改单机知识。已有知识组可通过建组弹窗的选择框管理名称、成员和删除，也可从知识面板进入管理。
- 知识面板区分“组知识”和“本机知识”，展示公共内容供多少台成员使用、当前会话关联多少台。组内服务器在单服务器或多服务器会话中均可使用公共知识，同一个组每轮只附加一次；本机差异仍单独附加。已存储在不同位置的重复正文不自动删除或按文本合并。
- 组知识支持独立的关闭／只读／可更新模式，创建后默认为只读；它不跟随单机知识模式一起开关。切换为可更新后，AI 可以整理、创建和更新公共文档，沿用执行权限：全局只读禁止保存，询问模式确认后保存，自动模式直接保存。AI 不能创建组或修改成员。组知识的附加设置、上下文预算、导入导出、版本检查和恢复与单机文档一致。
- 单机文档可“复制到组知识”。确认适用范围后进入公共文档草稿，检查并保存后才写入，原文档保留；不会复制原文档的来源关联。用户应只共享适用于整个组的内容。
- 可更新模式会引导 AI 在完成任务时主动沉淀新确认、可复用的组共同知识，复用已有文档并跳过未变化或重复内容。可以直接在会话中说“整理这组机器的部署路径和发布流程，保存公共知识，单机差异分别记录”；不需要手写文档。普通巡检和瞬时状态仍不自动归档。
- 工具搜索／读取／保存组知识使用 `groupId`，单机使用 `connectionId`，两者不能同时指定。组目录只给出本次会话已选择的成员 ID；选择一个成员不会授权操作其他组员。提示词要求优先采用明确的单机例外，并在操作前核验可变事实，这属于模型使用规则，不是对知识内容真实性的自动证明。
- 调整组成员或删除组会使进行中的旧组访问失效，旧编辑不能覆盖新范围；后续请求重新获取最新范围。删除知识组会删除其公共文档与版本记录，各台服务器的单机知识保留。已发送到 AI 的内容和既有会话历史不会撤回。

## 组合业务系统

知识组既可以保存同构服务的共同约定，也可以描述不同服务器协作组成的业务系统。建组时可勾选“这些服务器分工协作，组成一个业务系统”，创建 `SYSTEM.md`；已有组也可点击“添加系统说明”。不勾选时，现有公共文档的行为保持不变。

系统说明包括整体用途、对外入口、发布顺序与排障路径，以及服务角色和依赖。角色绑定组内的具体连接身份，允许同一服务器承载多个服务；依赖引用角色 ID，可记录协议和用途。角色与依赖均区分已确认／待确认，虚线表示待确认。界面展示关系图、完整角色与依赖列表；窄窗口可横向浏览图。

系统说明仍是组内的一份知识文档，支持每轮附加、按需读取、AI 更新、版本冲突检查、历史恢复和 Markdown 导出。AI 在可更新模式下使用 `knowledge_save` 的 `system` 字段更新 `documentId=system`，沿用已有执行权限；不能由此增删组成员。未核实的关系只能标为待确认，不能当作已确认事实保存。正文由应用根据结构生成，避免图与正文各自维护而失去一致性。单机目录和特殊配置仍保存到对应服务器。

AI 可以通过组内 `knowledge_search` 分页读取成员目录与身份绑定，用于记录完整业务关系。目录中的成员不代表远程操作授权：只有 `operableConnectionIds` 对应当前会话已选服务器。知识库的角色关系不会自动连接其他机器。

组成员变更或连接地址、端口、账号变化后，旧角色绑定不会自动改指向。界面显示关联失效，AI 读取时返回 `staleSystemNodes`；保存时必须先修正身份关联。恢复旧版本会保留当时的关系和身份，失效引用仍会标识出来。关系图是已存知识，不是实时探测结果；操作前仍需核验。

## 单机与公共文档管理

- 所有内容在同一个知识库中管理，编辑时可勾选“每轮附加”。短事实、固定路径和用户规则可以直接保存并勾选，无需另建来源文档或重复维护摘要；详细清单、步骤和排障记录默认按需读取。
- 优先记录可复用的“服务 → 路径／命令”：服务安装目录、配置和日志位置、已确认的更新／部署脚本路径及使用方式、验证过的启停命令或 systemd 单元。路径和用法需要证据，不根据名称猜测；尽量简短记录，避免自动扩写为整台主机的巡检报告。
- 单机空知识库启用时创建 `MEMORY.md`，默认每轮附加，也可以取消勾选。它继续支持原有条目格式：建议约 300 字符，此格式当前最多 6 条、共 600 字符，每条为单行、最多 160 字符。这只是初始编辑格式和预算，不是所有知识记录的统一条目限制；也可直接新建 Markdown 短记忆并勾选每轮附加。
- 来源关联可选，最多 3 份同服务器文档；只在需要追溯详细资料时关联。预览中可直接点击打开，改名不影响关联，删除后显示失效，不会自动匹配同名文档。移除失效关联后，独立记忆仍可保存。修改历史和版本恢复会保留关联及附加选项。
- 旧版自由文本记忆保留原文，编辑时可整理为条目，来源仍然可选。不会按标题猜测关联，也不会自动重写现有知识。临时负载、占用比例和扫描输出留在对话中，不反复作为长期事实附加。
- AI 保存规则明确排除瞬时状态：观测到的 PID、运行时长、实时 CPU／内存／swap 占用、负载、磁盘已用／剩余空间或使用率、当前进程／服务／容器状态及运行数量、临时会话和连接数。此规则同时适用于记忆和按需文档；普通巡检不应顺带建档。混合输出只提取有后续价值的稳定事实，没有新增长期信息就不保存。持久配置中的资源限制、容量、告警阈值与实时占用分开处理；主机用途、固定路径、用户规则和验证过的可复用操作步骤仍可记录。更新旧记录时也不应照抄其中的瞬时状态。这是系统提示词和工具描述对模型的约束，不是正文关键词过滤器；已有文档和用户手动编辑／导入不自动清理。
- 支持 Markdown 预览、编辑、新建、从本机导入和导出到用户选择的位置。导出的是已保存版本，编辑后应先保存。有来源的记忆导出附文档 ID，没有来源的记忆只导出正文；单独导入 Markdown 不会重建本机关联，如需关联可手动选择来源。导出不保留“每轮附加”选项，导入后默认按需读取。
- 每个知识范围（单机或知识组）最多 20 份文档，每份正文最多 32 KiB（按 UTF-8 字节计算）。界面在超限时提示并阻止保存。
- 每份文档保留最近 5 个旧版本，标明时间和用户／AI 作者。恢复旧版本会创建新版本；删除会同时移除该文档的历史。
- 多个会话同时修改时按版本检查，过期编辑不会覆盖新内容；保留当前草稿，用户可刷新并重新整理。

## AI 工具

会话中存在已启用的服务器知识或组知识时提供以下本地工具；它们不调用远程命令，也不向外部 MCP 服务暴露操作电脑文件的能力。任意服务器知识或组知识为可更新时提供保存工具，各目标的模式由后端单独检查。

| 工具 | 行为 |
| --- | --- |
| `knowledge_search` | 在一个授权服务器或知识组内搜索标题和正文；空查询列出文档。 |
| `knowledge_read` | 按文档 ID 分段读取最新内容和版本。长文档使用 `nextOffset` 继续读取，并通过 `expectedRevision` 避免混合不同版本。 |
| `knowledge_save` | 普通记录传 `content`，短记忆可设置 `alwaysInclude: true`；`memory` 继续传 `memoryEntries: [{ text, documentIds? }]`。来源可省略或为空；提供时必须存在、属于同一服务器且不是摘要自身。现有文档必须带准确版本；更新未传附加选项时保留原值。没有任意本地路径参数。 |

每轮对话开始，应用附加已勾选记录的内容，以及预算内的文档目录和可选来源元数据。已经足够清楚的独立记忆可直接使用，不必再次读取来源；需要完整步骤、证据、未包含的信息或实时状态时再搜索／读取／核验。来源失效不能提供细节依据，但不会自动使独立用户记忆失效。来源有效性由应用校验，检索时机由模型判断，并非自动语义检索或强制拦截回答。

常驻内容和目录有总长度限制，多服务器、多记录时分配预算；截断时标记并提示 AI 按需读取全文或搜索完整目录。编辑界面说明“每轮附加”受上下文预算限制。旧自由文本记忆每台最多附加前 600 字符，原始全文仍保留。文档不能改变工具权限，也不能替代对实时服务状态的核验。

知识为只读时，请求中不提供 `knowledge_save`；会话中任一服务器或组可更新时提供该工具，但只读目标的写入仍由主进程拒绝。主进程每次执行时检查最新模式，旧请求或其他窗口已有的工具定义不能绕过限制。模式为可更新时，AI 更新继续遵循全局执行模式：“只读”禁止保存，“询问”需要确认，“自动执行”允许保存。即使模型把保存误报为只读，应用也按写入处理。组写入记录标明组名和成员数量，保存结果提供“查看文档”，直接定位对应服务器或组的文档。组写入可能影响当前会话外的成员，提示词要求只保存用户明确确认适用于全组的约定或已验证的共同事实；本机例外仍保存到对应服务器。这是模型使用规则，不是内容真实性的自动校验。

## 开发验证

`npm run test:ui -- --knowledge` 使用临时应用目录、真实 SQLite 存储与实际 Vue 组件，验证三档模式、首次启用确认／取消、只读限制与手动管理、编辑、导入导出、冲突保留草稿、版本恢复、多服务器隔离和结果定位，以及中英文、三种主题和窄宽窗口。文件选择／保存对话框由测试替身提供，不访问真实用户知识；原生导出 IPC 的权限、取消和应用关闭行为另有单元测试。

工具执行测试通过模拟 AI 流验证读取、审批、保存和下轮工具加载，不调用真实模型或 SSH 服务器。
